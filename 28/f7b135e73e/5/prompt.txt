# Plan: Distributed Validation with DistributedSampler + allreduce

## Context

Currently, every rank processes the **entire** validation set redundantly during eval. In DDP mode with N GPUs, this wastes N-1x compute on identical work. We want to shard the validation set across ranks using `DistributedSampler`, then aggregate metrics via collective operations.

## Changes (3 files)

### 1. `annotix_ml/train/eval.py` — Add `allreduce_eval_metrics()` helper

Add a new function after `do_eval()` (after line 132):

```python
def allreduce_eval_metrics(
    eval_metrics: dict[str, float],
    device: torch.device,
) -> dict[str, float]:
    """Average eval metrics across all distributed ranks via all_gather_object."""
    if not dist.is_enabled() or not eval_metrics:
        return eval_metrics

    world_size = dist.get_global_size()
    all_metrics = [None] * world_size
    torch.distributed.all_gather_object(all_metrics, eval_metrics)

    # Merge: for each key, average over ranks that reported it
    all_keys: set[str] = set()
    for m in all_metrics:
        all_keys.update(m.keys())

    result = {}
    for k in all_keys:
        values = [m[k] for m in all_metrics if k in m]
        result[k] = sum(values) / len(values)

    return result
```

**Why `all_gather_object` instead of `all_reduce`?** Per-atom-type and per-edge-type metric keys (`accuracy_node_Br`, etc.) may differ across ranks if certain atom types only appear in one rank's shard. `all_gather_object` of dicts handles this naturally by averaging only over ranks that have each key. For ~20 floats every N steps, the overhead vs NCCL all_reduce is negligible.
